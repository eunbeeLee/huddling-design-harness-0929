# 하네스 목적 (R2)

> 참조: `docs/story-service.md`(판정 기준) · `docs/story-work.md`(작업 흐름) · `docs/design.md`(가이드 SSOT)

## 1. 매번 달라지는 것 (실행 입력)

| 입력 | 형식 | 개수 규칙 |
|---|---|---|
| 대상 기능 | PRD 섹션 ID (예: `6-4`) | 실행당 정확히 1개 |
| 레퍼런스 | `refs/` 폴더의 스크린샷 (png/jpg) | 3장 이상 10장 이하 |

- 한 번 실행하면 대상 기능 1개의 화면 1묶음이 나온다.
- 레퍼런스는 사용자가 uibowl에서 직접 모아 `refs/`에 넣는다(수동 입력).

## 2. 사용자

| 누구 | 하는 일 |
|---|---|
| 디자이너 (본인, 1명) | 하네스를 실행하고, 판정 결과를 확인한다 |
| 내부 관계자 | 컨셉 확정 지점에서 `승인` 또는 `반려` 중 하나를 기록한다 |

## 3. 하네스 범위 (story-work 1~7번 대응)

| # | 작업 | 처리 방식 |
|---|---|---|
| 1 | 레퍼런스 수집 | 수동 (사용자가 `refs/`에 넣음) |
| 2 | 레퍼런스 분석, 반영 포인트 | 에이전트 |
| 3 | 화면설계서 | 에이전트 |
| 4 | 키스크린 2~3개 (390×844) | 에이전트 + Figma MCP |
| 5 | 컨셉 확정 | **사람 승인 게이트** |
| 6 | 토큰·컴포넌트·화면 디자인 | 에이전트 + Figma MCP |
| 7 | 가이드 위반 검토 | 판정 스크립트 (읽기 전용) |

## 4. 완료 기준 (한 문장)

대상 기능의 390×844 키스크린이 **2~3개** Figma에 있고,
판정 스크립트가 **design.md 위반 0건**과 **금지규칙 A·B 위반 0건**을 보고했으며,
컨셉 승인 기록이 **1건** 있으면 완료다.

### 완료 판정 체크 (스크립트가 셀 수 있는 형태)

- [ ] 키스크린 프레임 수: 2 이상 3 이하
- [ ] 모든 키스크린 프레임 크기: 390×844
- [ ] design.md 위반: 0건
- [ ] 금지규칙 A 위반: 0건 (예: 멤버 자료 공개 설정의 기본값이 `비공개`가 아님)
- [ ] 금지규칙 B 위반: 0건 (예: 판매 신청 흐름에 운영자 검수 단계가 없음)
- [ ] 컨셉 승인 기록: `승인` 1건
